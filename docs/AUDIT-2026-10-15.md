# Audit aplikasi dan kesiapan update — 15 Oktober 2026

PR: <https://github.com/thiends-88/barang-dan-aset/pull/18>

## Kesimpulan

**Pengujian operasional lolos, tetapi belum ada rekomendasi tanpa syarat untuk merge/update produksi.** Masih ada satu dependensi berstatus **high** (`xlsx`) yang belum diperbaiki. Jangan menyamakan CI hijau dengan audit keamanan bersih. Merge belum dijalankan dan server Proxmox produksi belum disentuh.

Audit berupa peninjauan kode, pengujian regresi API/render, interaksi UI terarah, pemeriksaan dependensi, simulasi migrasi, dan dry-run updater. Ini bukan jaminan seluruh bug telah ditemukan atau pengganti pengujian dengan salinan database produksi.

## Hasil verifikasi

- `npm test`: **234 API + 58 render lolos, 0 gagal**.
- Sebelum tambahan tes isolasi penghapusan master ledger, suite **233 API** diulang **lima kali**, semuanya lolos.
- Interaksi jsdom terarah: **4 pemeriksaan lolos** (Catatan tersedia, tidak ada input jumlah/tanggal, catatan lama terisi, PUT hanya metadata).
- `npm run build`: berhasil, `dist/` diperbarui untuk deployment tanpa compiler.
- Migrasi terisolasi dari `server/db.js` commit basis `2f9ddd1`, dilanjutkan init versi baru dua kali: data contoh uji tetap utuh, kolom baru lengkap, `integrity_check=ok`, `foreign_key_check` kosong.
- `bash -n update-proxmox.sh`: lolos.
- Updater `--dry-run --no-restart --force` pada branch sesi: selesai bersih; DB sandbox lolos integrity check. **Bukan eksekusi aktual terhadap systemd/Proxmox.**
- `git diff --check` untuk sumber (di luar bundle pihak ketiga `dist/`): lolos.
- `npm audit`: **0 critical, 1 high** tersisa pada satu paket langsung `xlsx` (dua advisory).

Pernah ada kegagalan intermiten pembersihan teknisi pada pengujian sesi sebelumnya. Tidak terulang pada lima putaran audit ini; diagnostik kegagalan ditambah agar record yang tertinggal terlihat. Penyebabnya belum terbukti, sehingga tidak diklaim sudah diperbaiki.

## Risiko keamanan yang masih terbuka

`xlsx@0.18.5` digunakan frontend untuk membaca spreadsheet dan backend untuk menulis template, bukan membaca unggahan Excel di server.

- Prototype pollution: <https://github.com/advisories/GHSA-4r6h-8v6p-xvw6>
- ReDoS: <https://github.com/advisories/GHSA-5pgg-2g8v-p4x9>

Registry npm yang dipakai proyek tidak menyediakan versi `xlsx` yang menutup kedua advisory (`npm audit`: `fixAvailable: false`). Tidak dilakukan penggantian diam-diam ke fork yang belum diverifikasi atau penghapusan dukungan Excel.

**Tindak lanjut sebelum rekomendasi produksi:** migrasikan parser ke distribusi resmi yang telah diperbaiki atau alternatif terverifikasi, uji ulang template dan impor semua format yang masih didukung, lalu ulangi audit/test/build. Sementara itu jangan membuka spreadsheet dari sumber tidak tepercaya. Pembatasan ini adalah mitigasi sementara, **bukan perbaikan kerentanan**. Jika pemilik tetap ingin merilis untuk pemakaian internal, penerimaan risiko ini perlu eksplisit.

## Checklist Proxmox (setelah risiko diputuskan dan PR di-merge)

1. Pastikan path aplikasi, unit systemd, port dan Node.js ≥22 sesuai server sebenarnya. Jangan menyalin path contoh tanpa mengecek.
2. Unduh cadangan DB melalui aplikasi dan simpan di luar server; snapshot LXC/VM bila tersedia. Jangan menjalankan `api-test.mjs` atau endpoint reset/clear pada produksi.
3. Pastikan `AUTH_SECRET` acak sudah diset dan semua password akun contoh sudah diganti. Jangan mengekspos aplikasi ke internet terbuka tanpa kontrol akses/TLS yang sesuai.
4. Ambil updater **dari main sesudah merge**, tanpa reset kode lebih dahulu:

   ```bash
   cd /opt/barang-dan-aset  # sesuaikan lokasi aktual
   git fetch origin main
   git show origin/main:update-proxmox.sh > /tmp/update-proxmox.sh
   bash /tmp/update-proxmox.sh --dir /opt/barang-dan-aset --dry-run
   sudo bash /tmp/update-proxmox.sh --dir /opt/barang-dan-aset
   ```

   Bila berbeda dari default, tambahkan `--service NAMA_UNIT --port PORT_AKTUAL` pada kedua pemanggilan. Jangan memakai `--no-restart` saat aplikasi masih menulis database.

5. Pastikan output commit berjalan sama dengan target, cek `/api/version`, lalu uji login, stok, bon, histori servis dan pengembalian pelanggan. Pastikan jumlah data sesuai cadangan.
6. Bila update gagal, simpan log dan cadangan. **Hentikan layanan sebelum rollback kode/DB**; jangan menyalin DB di atas proses aktif. Setelah rollback, instal dependensi versi sebelumnya lalu start dan verifikasi kembali. Jangan menghapus cadangan sebelum verifikasi selesai.
